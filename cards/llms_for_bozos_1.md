## Neural Networks
[[tab]] Nearly all modern machine learning is built on neural networks. We care about them because of the [[cite(https://en.wikipedia.org/wiki/Universal_approximation_theorem)]]{Universal Approximation Theorem} which says that a neural network with a single layer$^{\text{with sufficient width}}$  and appropriate activation function can be used to approximate any continuous function to any desired degree of accuracy.  [[note(right, type: relative, orient:horizontal)]]{}{In reality it is heavily debated what LLMs actually "learn". Many argue they are 'stochastic parrots' that convincingly interpolate between training data to spit out believable responses. Others believe that in approximating the underlying distribution of language, models learn the rules of the world that generated it.} The bet behind LLMs is that by training sufficiently large networks to learn the underlying distribution of language, we are training a general model of the world. 

[[bigbreak]]
### The Neuron
[[tab]] Neural networks are surprisingly simple at their core. A single neuron contains a trained weight vector, $\vec{w} = [w_1, w_2, ... , w_n]^T$, and bias scalar $b$. Given an input vector $\vec{x} = [x_1, x_2,..., x_n]^T$,  each neuron computes $z = \vec{w}^T\vec{x} + b$. $z$ is then put through a non-linear activation function g(z). 

[[bigbreak]]
### The Layer
[[tab]] Individual neurons are organized into layers. A layer is simply a collection of independent neurons that together, project our input data into a different dimension. If we have n features, our input vector $\vec{x}$ lives in $\mathbb{R}^n$. Then for a layer with $m$ neurons, each will have a weight vector $\vec{w} \in \mathbb{R}^n$, which we can express as a weight matrix $W \in \mathbb{R}^{m \times n}$ (simply all the weights stacked on top of each other).  We can similarly stack each neuron's bias scalars to form our bias vector $\vec{b}$. Our output vector for the entire layer is now $\vec{z} = W\vec{x} + \vec{b}$. Overall, the layer performs an affine transformation $T(\vec{x}): \mathbb{R}^n  \rightarrow \mathbb{R}^m$.
[[break]]
[[tab]] If we stopped here, and chained layers together like this, we wouldn't actually be able to learn much. We would be left with a series of affine transformations on our input data. The product of two affine transformation matrices is also affine, meaning we would simply be doing a series of scales, rotations, shears, and translations to our input vector. No matter how many layers we have, they would all collapse into a single affine transformation and we could only learn affine functions. This is why we introduce activation functions: we pass the affine output through a non-linear function that "folds" the vector space into complex shapes. We are then left with many linear segments (one per neuron) that are used to approximate any arbitrary smooth multi-dimensioned function.
[[note(right, type:relative, orient:horizontal)]]{}{Visualization shows an example of how with more separating planes, we can better fit the surface of complex distributions. Try changing the number of neurons, or enter a new function to fit.}
[[viz(type: neuron-approx, height: 380, width: 320, align: center)]]
[[tab]]Three types of layers make up a network. An input layer takes raw data (pixel values, word encoding, sensor readings, etc) and compresses it down to a dense latent representation. 
[[break]]
[[tab]]Followed by a series of "hidden" layers (hidden because they do not directly interface with the real-world data, and because they are used to learn higher dimensional relationships) that project their input layers into a higher dimensional space.  [[note(left, type: relative, orient:horizontal)]]{}{For a concrete example here, imagine that we are working with a "dictionary" of 50,000 words that the model recognizes. Then every single word is encoded as a unique vector in $\mathbb{R}^{50,000}. $ The input layer will take the vector corresponding to some word we feed it, and project it into a continuous latent vector space, e.g. $\mathbb{R}^{4096}$. Every hidden layer will then expand its input from $\mathbb{R}^{4096}$ to e.g. $\mathbb{R}^{16384}$. After it applies its activation function, it will then recompress back to $\mathbb{R}^{4096}$ , add it to the input vector, and pass it on to the next layer. Finally, the output layer will take our $\mathbb{R}^{4096}$ vector that has been enriched by the hidden layers, and project it to our original $\mathbb{R}^{50,000}$.}  We are going from a dense lower-dimensional representation of information into a much sparser high-dimensional space. This helps to better isolate features. We have many more neurons to work with that activate under more specific circumstances which creates sparsity in our activations and more unique combinations. So where in lower dimensions, multiple features share the same dimension, in higher dimensions operations have the room to occupy their own dimensions and act on more specialized tracts of neurons. 
[[break]]
[[tab]] Finally, we have an output layer which takes the vector produced by the final hidden layer and undoes the transformation done by the input layer,  projecting it back into our original vector space. 

[[bigbreak]]
### The Network
[[tab]] A neural network is made up of an input layer, hidden layer, and output layer. Two or more hidden layers makes it a 'deep' neural network. Much of the power of neural networks in modern machine learning comes from chaining layers together in these deep networks. In theory you can learn any underlying distribution in a neural network with a single hidden layer with enough neurons. In practice we see that using a single large layer ends up brute-forcing the distribution, each neuron represents some highly localized feature in what we are trying to represent. In other words, the network's ability to create distinct linear segments grows linearly with width. For a function that is 10x as complex, we need 10x the number of neurons.
[[break]]
[[note(right, type:relative, orient:horizontal)]]{}{One nice way to think about the effects of having multiple layers is through image processing. If we are training a network to recognize faces, the first layer may implicitly learn to detect edges, the second curves and corners, the third features of the face, and a final layer specific faces. If we only had one layer, we would be expecting the single hidden layer to learn the weights to go from pixel values to the abstract concept of a face.}
[[tab]]  This is why depth matters. A single layer acts as some non-linear function, multiple layers chained together act as multiple composed functions. This allows for each layer to learn more abstract concepts rather than relying on a single layer to make the leap from input to output. 
[[break]]
[[tab]] I also want to take some time to talk about what our input data looks like as it goes through a network. Think about processing an image of a face, the same image shifted by a few pixels may look completely different when comparing them pixel by pixel in the input space.  The input space is chaotic, vectors carry no semantic meaning. When the raw data passes through the first hidden layer, we know that it projects it into a latent space. These latent spaces are what is learned when we talk about training a neural network. Every layer's weights and biases evolve through the training process to learn various aspects of the training data.  Now, in a well-trained network, axes in the latent space represent more meaningful concepts: for example when processing text some axis may represent "negative tone" or "plurality". 
[[break]]
[[tab]] One remarkable quality of latent spaces is that they let us perform linear algebra operations on concepts. One of the most famous examples is that given vectors for different words in this space, we can expect the following to be true: $\vec{v}_{king} - \vec{v}_{man} + \vec{v}_{woman} \approx \vec{v}_{queen}$. We can also calculate the distance between vectors to gauge semantic similarity, we expect king and queen to be roughly next to each other in space, separated by the same distance that man and woman are. 
[[break]]
[[note(left, type:relative, orient:horizontal)]]{}{Going back to the image processing example,  in our initial data there is no nice way to tell apart dog from cat but we know that there are definitive concepts that make dogs dogs and cats cats. As we go through the hidden layers, the goal of the network is to take our initially meaningless space and "untangle" it till all dog-concepts are clustered together, and all cat-concepts are clustered together. }
[[tab]] The input space, as we saw previously, has no meaningful geometry. But the data is not random, it lives on some smooth surface (a manifold), there is a fundamental reality that dictates the similarities and differences between concepts. The ultimate goal of all of our layers is to progressively unfold this manifold until we end up in a vector space where all of these concepts are clustered together with meaningful relationships between them. This manifold exists regardless of the space we are in, each layer projects it into a new space that exposes different structure. 

[[bigbreak]]
### Training a Network
[[note(right, type:relative, orient:horizontal)]]{}{We define our own loss function for the distribution we are training the data to learn. All the loss function does is find the distance between where the data actually landed in our final latent space, and where it should have landed.}
[[tab]] Before we can do anything useful with a network, we need to train it. All of the neurons are initialized with completely random weights and biases. Geometrically, our network is effectively randomly stretching and folding our input data, with our inputs ending up at arbitrary positions in the final latent space. To train a network, we feed it many labeled examples. Data will flow through every layer and make a final prediction. We use a mathematical loss function to calculate how far from reality that prediction was.
[[break]]
[[tab]] Once the network knows how wrong its guess is, it uses an algorithm called gradient descent to adjust the weights in the right direction. It does this with backpropagation: going backwards through every layer of the network and calculating by how much it needs to tweak its weights and biases. Through thousands of these small adjustments, the network iteratively remodels the mesh formed by all of the piecewise segments represented by the hidden layers to fit the geometry of the underlying function. The visual below shows you how iterative weight updates gradually fit an arbitrary function.
[[viz(type: gradient-descent, height: 380, width: 320, align: center)]]
[[tab]] There is a lot of nuance and literature in training that I am glossing over here for the sake of brevity. To learn more about the training process and how neural networks work in general, I highly recommend taking a look at Andrej Karpathy's [[cite(https://karpathy.ai/zero-to-hero.html)]]{Neural Networks: Zero to Hero}. He goes over building neural networks from scratch, with lots of valuable intuition about what each step in the process is actually doing. 
[[bigbreak]]
### Inferring a Network
[[tab]] Once training is complete, we can lock the weights and biases of the network in place (given faith that they have actually learned the desired distribution) and use them for inference. Inference means feeding the network new data and letting it predict based on the distribution it learned during training.
[[break]]
[[tab]] Compared to training, inference is much more straightforward. When we talked about the layers of a network we saw that all of the work for a single layer is simply $\vec{z} = W\vec{x} + \vec{b}$ followed by an activation function. Given an input vector, we do our sequence of matrix multiplications, adding biases, and computing activation functions until we reach the output layer. [[note(left, type:relative, orient:horizontal)]]{}{One way to look at this is that discriminative machine learning will compute "slices" of the manifold in latent space at training time, and during inference we just have to find where among the slices our data belongs. For generative inference, we take each part of the input and "walk" across the manifold to find the portion that is most likely to follow the input.} For discriminative inference (tasks like classification), the output layer draws a hyperplane through the final latent space. Which side of the plane your data lands on is the prediction. For generative inference (things like LLMs or image models), a modern architecture like transformers transforms the input vector into a final vector in the latent space. The output layer considers the distance between that vector and every other known vector in its dictionary. For example given "the monkey ate the ", we might find that the final vector is a 90% match to "banana", a 5% match to "apple" and a 0.0001% match to car. It will append "banana" back to the input, and run the whole sequence again.

[[bigbreak]]
##  Transformers
 [[note(right, type:relative, orient:horizontal)]]{}{Fun fact, the GPT in ChatGPT stands for "generative pre-trained transformer". Generative in this case meaning it is used to generate text and pre-trained meaning it uses the gradient descent based weight-adjusting scheme we described earlier.}
[[tab]] Given you should now have some intuition around the fundamental concepts of neural networks, let's move onto the basis of LLMs (and most other modern parts of machine learning): the Transformer. Transformers were introduced in Google's seminal 2017 paper [[cite(https://arxiv.org/abs/1706.03762)]]{Attention is All you Need} (Vaswani et al.).

[[bigbreak]]
### From Words to Tokens
[[tab]] We know that neural networks operate on vectors of numbers, not strings of text. Before we can do any computation we have to convert our raw text into something that the model can work with. One naive approach may be to assign an integer to each unique word in the English language, but this falls apart quickly. We would need to maintain a massive vocabulary to cover every word the model might encounter, and it would have no way to process a word it had never seen before.
[[break]]
[[tab]] LLMs solve this problem with subword tokenization. They use algorithms like byte-pair encoding (BPE) to break text into smaller common reusable pieces called tokens. Under BPE, a word like "newer" may become ["new", "er"] and a longer one like  "dehumidifier" may become ["de", "hu", "mid", "if", "ier"]. The model then maintains a fixed vocabulary of tokens to compose any new words, for example LLama 3 has a vocabulary of 128,000 tokens. Each token has some corresponding learned vector, its embedding, that lives in the model's latent space. Earlier we described the input layer to a neural network, for a transformer this embedding lookup is our input layer. Every time we put text into a model, we split it into tokens, look up each token's embedding vector, and then feed that sequence of vectors to the model. Similarly, the model will spit out vectors that we compare against the full vocabulary to choose which token comes next.

[[bigbreak]]
### Context, Ambiguity, and Attention
[[tab]] One of the core problems with vanilla neural networks is that every token has a single fixed position in latent space. No matter what came before it, if the network sees "bark" it will always assign it the exact same vector. This is unlike real language where meaning is highly dependent on the context; bark means something very different depending on whether we're talking about a dog versus a tree. This is the problem solved by *Attention*, introduced by [[cite(https://arxiv.org/pdf/1409.0473)]]{Neural Machine Translation by Jointly Learning to Align and Translate.} (Bahdanau et al. 2014).
[[break]]
[[tab]] The original transformer was designed for translation which has a natural divide between input and output. French went in, and English came out. The architecture mirrored this: an encoder would read the input sequence and compress it into a latent representation, and a decoder would take that representation and generate the output in English a token at a time. The encoder is allowed to look at all other tokens in the input regardless of position, because when you are trying to understand a sentence you should have the full context. The decoder is only allowed to look at tokens that came before it, because you can not condition your next token based on tokens you haven't generated yet. LLMs do not use this encoder-decoder break, there is no clean split between input and output in conversation. The prompt and response are treated as being one continuous stream of text. We keep only the decoder and treat input tokens the same as output tokens, only looking at the tokens that came before them. 
[[break]]
[[tab]] Attention solves this problem by having tokens in a sequence look at every other token, evaluate their relationship, and adjust their own meaning based on their neighbors. The vector for "bark" will always start off at the same point. After attention, its vector shifts. "bark" in a sentence after "tree" means something very different from "bark" somewhere in a sentence after "dog" or "peppermint". Concretely, Transformers implement this by taking every token's starting vector and multiplying it by three different weight matrices to create three new vectors for each token: the query (Q), the key (K), and the value (V).The query represents what the current token is "looking for". "bark" may project a vector that says "are there any tree or dog related tokens around me?".  [[note(left, type:relative, orient:horizontal)]]{}{If you are struggling to reason about how the Q & K vectors can represent so many different concepts, it can help to remember that we are working in high dimensional spaces like our $\mathbb{R}^{4096}$ example from earlier. So if axes #5 represents noun-ness, axis #500 represents roughness, and #838 represents being a loud sound, we might see that the key vector for "bark" has spikes on those axes.} The key represents what the current token is. "bark" may signal "I am a noun", "I am an object that can be rough", and "I am a loud action/sound" simultaneously.  Finally, the value vector is the pure meaning of the token that gets transmitted to other tokens, its job is to move other vectors to more context aware locations in latent space.
[[break]]
[[tab]] What makes this system so powerful is that it decouples what about tokens makes them a good match for other tokens, and what they mean. When we see a sentence like "the fluffy dog barked",  "fluffy" broadcasts "I am a tactile adjective looking for an animal or furniture noun". But the meaning of fluffy doesn't matter in that matching process. 
[[break]]
[[tab]] The attention computation is very simple, each token in the sequence does a dot product between its query vector, and every other token's key vectors. Q and K pointing in the same direction implies semantic similarity so their dot products will be high. Unrelated vectors will be orthogonal and their dot product produces zero. Once we have done this computation for a single token, we put all of the vectors through a softmax, a computation that transforms all of them into values summing to 1. This gives us our attention matrix.  However, as we increase the dimensionality of these vectors, $d_k$, these dot products can grow to be very large. When we put the attention vectors through the softmax we could often end up in scenarios where a single score becomes 1.0 and all others are 0.0, killing any ability to learn from multiple tokens at once.
[[break]]
[[tab]] To fix this we scale the dot product. We divide the result by the square root of the dimension of the key vectors $\sqrt{d_k}$. This keeps the values in a stable range, ensuring the softmax produces a smooth distribution of probabilities. This operation is known as scaled dot product attention, expressed as $\text{Attention(Q,K,V)} = \text{softmax}(\frac{QK^T}{\sqrt{d_k}})V$
[[break]]
[[tab]] Going back to the fluffy dog, if we are computing attention scores for the token "barked" we might see something like:
[[break]]
| Token    | Score | Rationale |
| :--- | :------ | :---- |
| The        |   0.03   | Not necessary to "barked" for meaning |
| fluffy    |   0.08   | Might give slight reasoning to type of thing that barked, but not core to meaning. |
| dog    |  0.65   | Tells "barked" that it is a dog that is barking, the core of what we were looking for. |
| barked |  0.24   | Attending to itself, make sure barked preserves some of its baseline meaning. |

[[note(right, type:relative, orient:horizontal)]]{}{In practice we would just take all the tokens in our sequence, and create a matrix of all of their Q and K vectors stacked on top of each other to get a query matrix and a key matrix. Multiplying these together gets us our final matrix of attention scores.}
Remember that this is only the attention computation for the token "barked" we would also do this for every other token in the sentence.  For each token, we then get a new context vector with the simple calculation $\vec{x}_{context} = \sum score_i \times V_i$. In other words, it is just a linear combination of each value vector and its corresponding attention score. This should make intuitive sense, if "dog" matters the most to the meaning of "barked" then we should weigh its value contribution to "barked"'s meaning more than "fluffy".We then add the original vector back: $\vec{x}_{new} = \vec{x}_{original} + \vec{x}_{context}$. This residual connection ensures we are enriching the original vector, not replacing it.Finally, we do a normalization step to make sure vector magnitudes do not grow boundlessly across layers.

[[bigbreak]]
### Positional Encoding
[[tab]]  There is one glaring issue with this system. We know tokens "attend" to other tokens to try and gain context, but the simple dot product we use to calculate similarity does not know anything about token positions. The sentences "The dog bit the man" and "The man bit the dog" look mathematically identical to attention.
[[break]]
[[tab]] Before any token is put through any part of the model we stamp it with a positional encoding. Each vector will have a unique signature the model can learn to recognize where in the sequence each token belongs in. This is as simple as adding on a position vector to each token's original vector: $\vec{x}_{input} = \vec{x}_{token} + \vec{x}_{position}$.
[[break]]
[[tab]] This lets the model learn position-dependent relationships during training.  A query like "I need a noun" shouldn't match every noun in the sequence equally. Positional encodings let the model learn that nearby nouns matter more than distant ones. If we have the token "blanket" much earlier in our sequence and then we see "the fluffy dog", we shouldn't attribute fluffy equally to dog and blanket. We should know that fluffy probably doesn't attend to blanket because of how far back it is.
[[break]]
[[tab]] Most modern models generate these embeddings through [[cite(https://arxiv.org/pdf/2104.09864)]]{Rotary Positional Embeddings (RoPE)} (Su et al. 2021). What RoPE does is instead of adding a static vector at the start, we rotate all of our vectors during the attention computation. We have some rotation amount $\theta$, and the token at position $n$ gets rotated by $\theta n$. This works perfectly for attention because scores are calculated with a dot product, which depends on the angle between two vectors. With RoPE, two tokens separated by the same distance always have the same relative rotation, regardless of where they appear in the sequence. This gives models a natural bias toward attending to nearby tokens. In short, Attention Score $\propto \cos(\theta_m - \theta_n)$.

[[bigbreak]]
### Making Meaning from Context
[[tab]] Each token now carries a context-enriched vector: its original embedding plus a weighted blend of its neighbors' meanings, normalized. Each vector now goes through a feed-forward neural network. There is no cross-token communication here, every vector is put through the exact same network independently. 
[[break]]
[[tab]]
When our context-enriched vector for "barked" comes out of the attention mechanism, it has absorbed the geometric position of "dog" but the vector "barked + dog" doesn't really mean anything, it is just a coordinate in space. It is up to the network to say "this coordinate corresponds to the sound that a small house-pet canine makes". This is the same kind of feed-forward network we covered earlier. Its weights were just trained specifically to interpret the outputs of attention. 
[[break]]
[[tab]] Finally, similarly to the end of the attention stage,  we do a residual connection followed by a normalization. We add the input to the feed-forward network to the output vector it produces to make sure we do not completely lose the original context we started with, and we normalize that final vector to make sure it lives in a range that following layers recognize.

[[bigbreak]]
### Generating a Token
[[note(right, type:relative, orient:horizontal)]]{}{This sequence is called a post-norm architecture, which is what is described in the original transformer paper. Modern models have moved to a pre-norm architecture in which we have Normalize $\rightarrow$ Attention $\rightarrow$ Residual $\rightarrow$ Feed-Forward Network $\rightarrow$ Residual. This is largely for gradient stability during training time.}
[[tab]] The sequence we have described above, Attention $\rightarrow$ Residual & Normalize $\rightarrow$ Feed-Forward Network $\rightarrow$ Residual & Normalize, represents a single transformer block/layer. [[note(left, type:relative, orient:horizontal)]]{}{There is a field called mechanistic interpretability that focuses on trying to figure out what exactly it is that models learn, and where they learn these things. There is a lot of interesting work being done on things like [[cite(https://dnhkng.github.io/posts/rys/)]]{figuring out what different layers in a pre-trained model do} or [[cite(https://www.anthropic.com/research/emotion-concepts-function)]]{mapping neuron activations to human emotions.}} These layers relate to each other the way hidden layers do in a plain neural network. Earlier layers tend to learn things like parts of speech or syntax and grammar, middle layers shift to semantics and longer-ranged relationships, and later layers may represent abstract task-specific concepts. None of this is explicitly wired into the model. We never tell layers to learn grammar or layer 20 to learn semantics. These relationships emerge during training. 
[[break]]
[[tab]] After every token in our input goes through the sequence of transformer blocks, each enriched with progressively deeper context, we're ready to generate new tokens. After the final block, only the last token's vector matters. By now, the vector encodes the full context of every preceding token; relationships, meanings, and structure are compressed to a single point in latent space. [[note(right, type:relative, orient:horizontal)]]{}{The LM head is actually interchangeable. We could just as easily replace it with a classification head that will give us a binary yes/no on if the sequence is spam, or a regression head that maps that final vector to a number from 0-100 to tell us how angry a customer was for sentiment analysis.}  We put this single vector through an output layer called the Language Modeling (LM) head. Just like the final output layer in a neural network we described earlier, this LM head simply takes the vector passed into it and maps it against the vocabulary of tokens that the model recognizes. This creates probabilities for every token in the vocabulary, so we can choose one to be our next token. We append the chosen token to the input and run the sequence again. One token is generated per pass, until the model emits a 'stop' token  or we reach a length limit.

[[bigbreak]]
### The KV Cache
[[tab]] There is one glaring inefficiency in this computation: we go through the entire transformer doing work for every single token in the input sequence for every single new token we want to generate, but most of the work we are doing is redundant. This is because during training and inference we apply causal masking. Tokens are only allowed to look at other tokens that came before them. When considering "The fluffy dog barked", "fluffy" is only allowed to look at "The" and "fluffy", it doesn't make sense to give tokens knowledge of the future. This means that we don't care about the queries those tokens broadcast anymore, so we maintain a KV cache.
[[break]]
[[tab]] Every time we generate a new token, we append its K and V vectors to a cache, forming two matrices that grow for every new token we process. When a new token goes through the pipeline, we just have to multiply its Q vector by the entire cached K matrix to generate attention scores and add the weighted V matrix. Instead of multiplying the full Q matrix by the full K matrix every step, we multiply a single query vector against the cached keys, reducing a matrix-matrix computation to a matrix-vector one.
[[bigbreak]]
### Attention Heads
[[tab]] One last fundamental topic to modern LLMs is the concept of attention heads. We talked about how attention produces enriched context vectors, but in practice we find that it isn't perfect at capturing relationships. It often ends up producing a muddled average of all of the tokens that were important to the token being attended to. Attention finds multiple tokens equally important but for different reasons and can only produce one blended context vector.
[[break]]
[[tab]] The solution to this is to split attention up into multiple heads that can all learn different concepts. For example, if we are working with a latent space in $\mathbb{R}^{4096}$ then we may have 32 attention heads that each work in $\mathbb{R}^{128}$. This gives us 32 distinct $W^Q$, $W^K$ and $W^V$ matrices that all have their own independent set of learned weights for every single transformer layer. The heads naturally learn to specialize; one head may solely try to look for the agent noun that drives some action, another may strictly look for the noun being acted on, another searches for modifiers, etc. 
[[break]]
[[tab]] Once we have all of our new context vectors after multi-headed attention, we stack them all together and multiply by a new output matrix $W^O$. This matrix smooths out the "seams" of where we stitched all of the individual attention matrices to resolve them into a single vector in the model's latent space. The output projection does three things, it reconciles all of the disjoint head inputs, rotates the concatenated vector back into the standard coordinate system, and lets the network weigh some heads more heavily than others.

[[bigbreak]]
## Next Steps
[[tab]] That is the full pipeline. Text gets split into tokens, each token looks up its embedding vector, and that sequence of vectors passes through a stack of transformer blocks. Each block runs attention to build context, feeds the result through a network to extract meaning, and adds residual connections to preserve what came before. After the final block, the last token's vector gets projected against the full vocabulary to pick the next token. Repeat until done.
